24G显存玩转Flux训练

AI-Toolkit

AI-Toolkit是一个高效的本地化Diffusion-like模型微调工具。它以process为执行的基本单位，每个process会有一个run函数。Flux训练过程在BaseSDTrainProcess中执行。

我们知道光Flux的transformer模块大小就有23.8G如此大的模型基本不可能直接加载到24G显存的消费级显卡上。如果想要顺利训练必须要使用一些trick。我们来看看AI-Toolkit是怎么管理VRAM的。

模型加载

模型加载部分主要是量化

这里要注意的是patch_dequantization_on_save(transformer)，因为一旦执行 freeze(transformer)意味着参数实现了量化，参数的值会发生改变(除以一个scale)。保存时需要反量化（乘scale），恢复原来的值：

同样被量化的还有T5文本编码器：

CLIP模型小所以就不量化，并且我们不训练文本编码器所以也就无需dequantization了。vae对出图效果影响巨大，一般我们不做量化。

训练及数据处理

训练时记得开启梯度检查点，梯度检查点 gradient_checkpointing 的工作原理是在反向传播时， 重新计算深度神经网络的中间值（而通常情况是在前向传播时存储的）。 这个策略是用时间（重新计算这些值两次的时间成本）来换空间（提前存储这些值的内存成本）

加载LoRA，后面会开坑详细讲一下LoRA构建的全流程，以及自定义adapters

数据处理部分做了latent cache，将训练图片过vae得到的latent保存到disk，避免每个epoch都重复计算latent。

总结

  1. 模型加载时做fp8量化，整个计算过程建议使用bf16。freeze(transformer)意味着将模型权重转化为了fp8但是由于现在pytorch底层还不支持fp8的运算，所以真正计算时，optimum-quanto底层是将参与计算的weight是通过dequantized = value * scale（optimum-quanto一般采用的都是线性量化）反量化并upcast到bf16的，value是量化后的值。
  2. latent cache，将latent做本地缓存减少对vae的调用。
  3. AI-Toolkit貌似没有做model offload，但实际上offloading虽然影响速度，但是能够进一步节省VRAM。Comfyui-FluxTrainer是做offloading的。
  4. 实测下来AI-Toolkit大概会用22G的VRAM。

原生diffusers

使用diffusers训练好处在于对模型的完全可控，但是显存的优化是一个挑战。一般有两个方向：
1. Quantification（量化） 2. Offloading

关键代码

代码中主要运用了两个关键技术

  1. apply_layerwise_casting

    storage_dtype：模型存储时类型（量化类型fp8）

    compute_dtype：模型计算时类型，在计算时upcast到此精度（bf16）

    skip_modules_pattern：跳过的模块

  2. apply_group_offloading

    gradient_checkpointing 技术是和apply_group_offloading冲突的，由于if self.group.onload_leader == module条件判断的存在导致由于参数的变化反向传播时并没有进行device swap。apply_group_offloading仿佛只是为推理设计的。如果需要apply_group_offloading在反向传播时依然生效需要修改~/hooks/group_offloading.py/GroupOffloadingHook

总结

使用原生diffusers进行训练需要注意使用量化和offloading，当然更多的tricks例如latent cache也是多多益善。对于初学者我还是建议使用AI-Toolkit进行模型的微调，因为AI-Toolkit内部还是有着大量的细节帮助我们管理计算资源，使得我们可以把精力放在模型训练这件事本身上。
